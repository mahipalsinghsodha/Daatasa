1. PROJECT OVERVIEW & ARCHITECTURE
This is a production-grade Ghee e-commerce web application built on the MERN stack (MongoDB, Express, React, Node.js). It is designed to operate at the scale and quality of a major Indian D2C brand. The system includes a full customer storefront, a multi-role admin panel, real-time features via Socket.io, Razorpay payment integration, subscription plans, live chat, and comprehensive order lifecycle management.

5. ORDER, PAYMENT & REFUND FLOWS
5.1 COD Order Flow
User adds items to cart → Cart page shows live price-preview (GET /api/orders/price-preview)
User clicks Checkout → Checkout page loads, user selects/enters address
User optionally applies coupon → POST /api/orders/verify-coupon → breakdown displayed
User places order → POST /api/orders {paymentMethod:'COD', shippingAddress, couponCode}
Backend: validate cart, validate stock, calculate price from DB settings, create order in transaction
Backend: reduce stock atomically, set paymentStatus='COD_CONFIRMED', generate invoiceNumber, clear cart
Backend: send order success email async
Frontend: redirect to Order Success page with order ID
5.2 Online (Razorpay) Order Flow
POST /api/orders {paymentMethod:'Online', ...} → creates order with paymentStatus='PENDING', stock reduced
POST /api/payment/create-order {orderId} → creates Razorpay order → returns razorpay_order_id
Frontend: opens Razorpay checkout modal with order amount
User completes payment in Razorpay modal
POST /api/payment/verify {razorpay_order_id, razorpay_payment_id, razorpay_signature, orderId}
Backend: HMAC verify signature, mark order PAID, generate invoiceNumber, clear cart, send success email
If payment fails/dismissed → POST /api/orders/fail {razorpay_order_id} → restores stock, deletes pending order, sends failure email
5.3 Cancellation & Refund Flow
User or admin calls POST /api/orders/:id/cancel {reason}
Backend checks: not delivered, not already cancelled
Restore stock for all order items
If paymentStatus=PAID + paymentMethod=Online + razorpay_payment_id exists → call razorpay.payments.refund()
Store refundInfo (refund_id, status, amount, initiatedAt) on order
Set paymentStatus='CANCELLED', save cancelReason, cancelledBy, cancelledAt
Send cancellation email (with refund info if applicable)
5.4 Return Request Flow
User: POST /api/orders/:id/return-request {reason} — only for delivered orders within 7 days
Admin: GET /api/admin/return-requests — see all pending requests
Admin: PUT /api/admin/return-requests/:id {status:'APPROVED'|'REJECTED'} — update status
On approval: trigger refund flow if online payment, send notification to user
5.5 Live Order Tracking (Socket.io)
Client connects to Socket.io on auth → joins room order:{orderId}
When admin updates order status → server emits 'orderStatusUpdated' to that room
Frontend Orders page and Order Detail page listen for this event → updates UI without reload
Admin ManageOrders page listens for 'newOrder' event → increments new order badge in real-time

6. SECURITY IMPLEMENTATION
The application implements enterprise-grade security across all layers. Below is the complete security checklist with current implementation status and required improvements.
6.1 Authentication Security — IMPLEMENTED
Security Measure
Implementation
JWT Access Token (15 min)
Stored in React memory (AuthContext state) — never localStorage/sessionStorage
JWT Refresh Token (7 days)
Stored in httpOnly, SameSite=Strict cookie — cannot be accessed by JS
Refresh Token Rotation
New refresh token issued on every /refresh call — old one invalidated
Token Version (tokenVersion)
Incremented on logout/password change — revokes ALL issued tokens
Password Reset Device Fingerprint
Hash of user-agent+IP stored at request time, verified at reset time
Bcrypt Password Hashing
Cost factor 12 — password field select:false in schema
Rate Limiting on Auth Endpoints
express-rate-limit: 10 req/15min per IP — skips localhost
OAuth Security
State parameter, callback URL whitelisted — Google + GitHub
Blocked User Check
isBlocked checked on every auth middleware call → 403 immediately
6.2 API & Infrastructure Security — IMPLEMENTED
Security Measure
Implementation
Helmet.js
Sets 14 security headers: HSTS, CSP, X-Frame-Options, XSS Protection, etc.
CORS Whitelist
Only ALLOWED_ORIGINS env variable values — localhost only in dev, strict in prod
MongoDB Injection Sanitize
express-mongo-sanitize strips $ and . from request body/params/query
